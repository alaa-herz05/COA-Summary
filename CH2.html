Addressability & Memory Locations

العنونة ومواقع الذاكرة
What is Addressability? ما هي العنونة؟

Every memory location must have a unique address. The CPU uses these addresses to identify and access data stored in memory.

Each address is a unique identifier for a specific memory location.
Arabic
كل موقع داخل الذاكرة يمتلك عنواناً فريداً خاصاً به. يستخدم المعالج هذا العنوان للوصول إلى البيانات المخزنة داخل الذاكرة. وتسمى عملية تحديد مواقع الذاكرة بواسطة العناوين باسم Addressability.
Address Bus & Memory Locations خط العناوين وعدد مواقع الذاكرة

The width of the Address Bus determines how many memory locations can be addressed.

Number of Memory Locations = 2n

Where:

  • n = Number of Address Bus Bits
Arabic
عدد المواقع التي يمكن الوصول إليها يعتمد مباشرة على عدد خطوط الـ Address Bus. كلما زاد عدد البتات زاد عدد العناوين المتاحة.
Examples of Address Bus Width أمثلة على عدد البتات
Address Bus Addresses Memory Locations
1 Bit 0,1 2¹ = 2
2 Bits 00,01,10,11 2² = 4
3 Bits 000 → 111 2³ = 8
8 Bits 00000000 → 11111111 2⁸ = 256
16 Bits --- 2¹⁶ = 65,536
32 Bits --- 2³² = 4,294,967,296
Arabic
احفظ القاعدة المهمة للامتحان: عدد المواقع = 2 أس عدد بتات Address Bus.
Calculating Addressable Memory حساب الذاكرة القابلة للعنونة

Knowing the number of locations alone is not enough. We must also know the size of each memory location.

The size of each location is determined by the Data Bus Width.

Arabic
حتى نحسب حجم الذاكرة الحقيقي يجب معرفة: 1- عدد المواقع. 2- حجم كل موقع تخزين. ويتم تحديد حجم الموقع بواسطة Data Bus.
Addressable Memory Formula قانون الذاكرة القابلة للعنونة
Addressable Memory = (Number of Storage Locations) × (Size of Each Location)
Addressable Memory = (2Address Bus Bits) × (Data Bus Width)
Arabic
هذا أهم قانون في جزء Addressability. غالباً يأتي عليه سؤال مباشر في الامتحان.
Solved Example 1 مثال محلول 1

Address Bus = 3 Bits

Data Bus = 2 Bits

Number of Locations = 2³ = 8
Addressable Memory = 8 × 2 = 16 Bits
16 Bits ÷ 8 = 2 Bytes
Answer = 2 Bytes
Arabic
لدينا 8 مواقع وكل موقع يخزن 2 بت، إذن الحجم الكلي = 16 بت = 2 بايت.
Solved Example 2 مثال محلول 2

Address Bus = 16 Bits

Data Bus = 8 Bits

Number of Locations = 2¹⁶ = 65,536
Addressable Memory = 65,536 × 8 = 524,288 Bits
524,288 ÷ 8 = 65,536 Bytes = 64 KB
Answer = 64 KB
Arabic
هذا المثال موجود حرفياً في السلايدات ويعتبر من أشهر أسئلة الامتحان.
Exam Questions أسئلة امتحانية
  • Computer with a 10-bit Address Bus: 2¹⁰ = 1024 locations
  • Computer with a 12-bit Address Bus: 2¹² = 4096 locations
  • Which bus determines the number of memory locations? Address Bus
  • Which bus determines the size of each location? Data Bus
Arabic
إذا رأيت سؤالاً عن عدد المواقع → استخدم Address Bus. إذا طلب حجم الذاكرة الكامل → استخدم Address Bus و Data Bus معاً.

Instruction Set Architecture (ISA)

معمارية مجموعة التعليمات
What is an Instruction Set? ما هي مجموعة التعليمات؟

An Instruction Set (ISA) is the complete vocabulary of commands that a CPU can understand and execute. It is the interface between software and hardware.

  • The language consists of 1s and 0s — machine language.
  • Different computers have different ISAs, but share many common concepts.
  • Early computers had very simple instruction sets (simplified implementation).
  • Modern computers: some simple (RISC), some complex (CISC).
Arabic Explanation
الـ ISA (Instruction Set Architecture) هو المفردات الكاملة للأوامر التي يفهمها المعالج وينفذها — الواجهة بين البرمجيات والعتاد.
اللغة عبارة عن أصفار وواحدات (Machine Language). كل نوع معالج له ISA مختلف، لكنها تتشارك مفاهيم كثيرة.
ظهرت مدرستان رئيسيتان: CISC (معقد) وRISC (مبسّط).

RISC vs CISC Architecture

المقارنة بين RISC و CISC
CISC — Complex Instruction Set Computer الحاسوب ذو مجموعة التعليمات المعقدة
  • Large number of instructions, of variable length.
  • Instructions have complex layouts and can perform multiple operations in a single instruction.
  • A small subset of complex instructions slows the entire system.
  • Memory access embedded directly in many instructions.
  • Example: Intel x86 architecture (>1000 instructions, 1–15 bytes each).
Arabic
CISC: عدد كبير من التعليمات ذات أطوال متغيرة. تعليمة واحدة يمكن أن تنفذ عمليات متعددة دفعةً واحدة.
المشكلة: مجموعة صغيرة من التعليمات المعقدة تُبطّئ النظام كله.
مثال شهير: Intel x86 — أكثر من 1000 تعليمة، كل تعليمة من 1 إلى 15 بايت.
RISC — Reduced Instruction Set Computer الحاسوب ذو مجموعة التعليمات المختصرة
  • Small but complete instruction set, hardwired for speed.
  • Each instruction performs one operation only.
  • All instructions are the same size (32 bits in MIPS).
  • Memory accessed only via explicit load and store instructions.
  • The compiler is responsible for producing efficient code.
  • Examples: MIPS, ARM, SPARC.   ~200 instructions, all 32-bit
Arabic
RISC: مجموعة صغيرة لكن كاملة من التعليمات، مُبرمجة بالأسلاك لتكون سريعة.
كل تعليمة تنفذ عملية واحدة فقط. كل التعليمات بنفس الحجم (32 بت في MIPS).
الذاكرة تُوصل فقط عبر load وstore. المترجم (Compiler) هو المسؤول عن توليد كود فعّال.
أمثلة: MIPS، ARM، SPARC.
Deep Dive: The Core Philosophical Difference الفلسفة الجوهرية للفرق

The underlying philosophy of RISC: "A system performs better when programs consist of only a few different instructions that are the same length and take the same number of clock cycles."

Performance Equation:   CPU Time = Instruction Count × CPI × Clock Cycle Time

RISC reduces CPI (Clock cycles Per Instruction) → fewer cycles per instruction.
CISC reduces Instruction Count → fewer instructions per program.
Arabic
فلسفة RISC: النظام يعمل بشكل أفضل عندما يتكون من تعليمات قليلة متماثلة الطول وتستهلك نفس الدورات.
معادلة الأداء: زمن المعالج = عدد التعليمات × دورات لكل تعليمة × زمن الدورة
RISC يقلل CPI (دورات لكل تعليمة). CISC يقلل عدد التعليمات في البرنامج.
Worked Example: Multiply 10 × 5 مثال محلول: ضرب 10 × 5

Consider computing 10 × 5 using CISC vs RISC:

CISC Version:

CISC Assembly (x86-style)
mov ax, 10 # load 10 mov bx, 5 # load 5 mul bx, ax # multiply in 1 instruction
Clock Cycles
2 × mov = 2 cycles
1 × mul = 30 cycles
Total = 32 cycles

RISC Version:

RISC Assembly (MIPS-style)
mov ax, 0 # accumulator = 0 mov bx, 10 # multiplicand mov cx, 5 # counter Begin: add ax, bx # ax += 10 loop Begin # repeat 5 times
Clock Cycles
3 × mov = 3 cycles
5 × add = 5 cycles
5 × loop = 5 cycles
Total = 13 cycles
Conclusion: RISC uses more instructions but fewer total clock cycles → faster execution (13 vs 32 cycles). RISC clock cycles are also shorter in duration.
Arabic Explanation
نفس العملية (10 × 5) على CISC تستغرق 32 دورة (mov بسيطة + mul معقدة 30 دورة).
على RISC تستغرق 13 دورة فقط (3 mov + 5 add + 5 loop) لأن كل تعليمة بسيطة = دورة واحدة.
النتيجة: RISC يستخدم تعليمات أكثر لكن دورات إجمالية أقل = أسرع في التنفيذ!

Arithmetic Operations & Assembly Translation

العمليات الحسابية والترجمة إلى لغة الأسمبلي
Basic Arithmetic العمليات الحسابية الأساسية

All MIPS arithmetic: 3 operands — 2 sources + 1 destination.

Format
add rd, rs, rt # rd = rs + rt sub rd, rs, rt # rd = rs - rt addi rt, rs, imm # rt = rs + immediate_constant
Design Principle 1: Simplicity favors regularity — always exactly 3 operands, never more, never less.
Arabic
جميع العمليات الحسابية في MIPS: 3 معاملات — وجهة واحدة + مصدران.
add: جمع سجلين وتخزين النتيجة في سجل ثالث.
addi: جمع سجل مع ثابت فوري (Immediate) — يجنب الحاجة لتحميل الثابت من الذاكرة.
Example 1: Simple Expression مثال 1: تعبير بسيط

C code:  f = (g + h) - (i + j);

Assume: f→$s0, g→$s1, h→$s2, i→$s3, j→$s4

MIPS Assembly
add $t0, $s1, $s2 # $t0 = g + h (temp) add $t1, $s3, $s4 # $t1 = i + j (temp) sub $s0, $t0, $t1 # f = $t0 - $t1
Arabic — الشرح خطوة بخطوة
خطوة 1: نحسب g+h ونخزن في $t0 (متغير مؤقت).
خطوة 2: نحسب i+j ونخزن في $t1 (متغير مؤقت آخر).
خطوة 3: نطرح $t1 من $t0 ونخزن النتيجة في $s0 (يمثل f).
MIPS لا يسمح بأكثر من 3 معاملات، لذلك نحتاج خطوات وسيطة.
Memory Operands: Load & Store عمليات الذاكرة: التحميل والتخزين

MIPS is a RISC architecture — memory accessed only via lw (load word) and sw (store word).

Key rules:
  • Memory is byte-addressed — each address = 1 byte.
  • Words must be 4-byte aligned (address divisible by 4).
  • Array element offset = index × 4 (since word = 4 bytes).
  • MIPS is Big Endian — most significant byte at lowest address.
Load/Store Format
lw $rt, offset($rs) # $rt = Memory[$rs + offset] ← LOAD sw $rt, offset($rs) # Memory[$rs + offset] = $rt ← STORE
Arabic
MIPS يصل للذاكرة فقط عبر lw (تحميل كلمة) وsw (تخزين كلمة) — مبدأ RISC الأساسي.
الذاكرة تُعنون بالبايت: كل عنوان = 1 بايت. الكلمة = 4 بايت، لذلك عناوين الكلمات يجب أن تكون مضاعفات 4.
عنصر مصفوفة رقم [i] = عنوان القاعدة + (i × 4).
Example 2: Array Access (Load) مثال 2: الوصول لمصفوفة (تحميل)

C code:  g = h + A[8];

g→$s1, h→$s2, base address of A→$s3

Offset calculation: index 8 → offset = 8 × 4 = 32 bytes

MIPS Assembly
lw $t0, 32($s3) # $t0 = A[8] (load from address $s3+32) add $s1, $s2, $t0 # g = h + A[8]
Arabic — الشرح
A[8] يعني العنصر الثامن في المصفوفة. كل عنصر 4 بايت، إذن الإزاحة = 8 × 4 = 32 بايت.
أولاً: نحمّل A[8] من الذاكرة إلى السجل $t0 باستخدام lw.
ثانياً: نجمع h (في $s2) مع A[8] (في $t0) ونخزن في g (في $s1).
Example 3: Array Access (Load + Store) مثال 3: مصفوفة (تحميل وتخزين)

C code:  A[12] = h + A[8];

h→$s2, base address of A→$s3

Offsets: A[8] → 8×4 = 32  |  A[12] → 12×4 = 48

MIPS Assembly
lw $t0, 32($s3) # $t0 = A[8] add $t0, $s2, $t0 # $t0 = h + A[8] sw $t0, 48($s3) # A[12] = h + A[8] (store result)
Arabic — الشرح
خطوة 1: نحمّل A[8] (إزاحة 32) من الذاكرة إلى $t0.
خطوة 2: نجمع h مع A[8]، نخزن في $t0.
خطوة 3: نخزن النتيجة في A[12] (إزاحة 48) بالذاكرة باستخدام sw.
لاحظ: اتجاه sw معكوس عن lw — نكتب من السجل إلى الذاكرة.
Example 4: If-Else Statement مثال 4: جملة الشرط

C code:

C Code
if (i == j) f = g + h; else f = g - h;

f→$s0, g→$s1, h→$s2, i→$s3, j→$s4

MIPS Assembly
bne $s3, $s4, Else # if (i != j) goto Else add $s0, $s1, $s2 # f = g + h (if branch) j Exit # unconditional jump to Exit Else: sub $s0, $s1, $s2 # f = g - h (else branch) Exit: ... # continue
Arabic — الشرح
MIPS يستخدم bne (branch if not equal) للانتقال إذا كان الشرط خاطئاً.
منطق الترجمة: نعكس الشرط — إذا كان i ≠ j نقفز لـ Else، وإلا ننفذ الـ if.
j: قفز غير مشروط — ينتهي من الـ if block وينتقل لـ Exit.
beq: يقفز إذا كانا متساويين. bne: يقفز إذا لم يكونا متساويين.
Immediate Operands المعاملات الفورية

Constants embedded directly in the instruction — no load required. Design Principle 3: Make the common case fast.

Examples
addi $s3, $s3, 4 # $s3 = $s3 + 4 (add constant 4) addi $s2, $s1, -1 # $s2 = $s1 - 1 (no "subi" needed — use negative) add $t2, $s1, $zero # $t2 = $s1 (register copy using $zero)
Arabic
addi: يجمع سجلاً مع ثابت فوري دون الحاجة لتحميله من الذاكرة — هذا يوفر تعليمة load.
لا يوجد subi في MIPS — نستخدم addi مع عدد سالب.
$zero: السجل 0 دائماً صفر — مفيد لنسخ السجلات (add $t2, $s1, $zero = نسخ $s1 إلى $t2).

Number Systems: Binary, 1's & 2's Complement

أنظمة الأعداد: الثنائي، مكمّل 1، مكمّل 2
Unsigned Binary Integers الأعداد الثنائية الموجبة

An n-bit unsigned number represents values from 0 to 2ⁿ − 1.

Formula & Example (8-bit)
Value = b₇×2⁷ + b₆×2⁶ + ... + b₁×2¹ + b₀×2⁰ Example: 0000 1011₂ = 0+0+0+0 + 1×8 + 0×4 + 1×2 + 1×1 = 11₁₀ 32-bit range: 0 to 4,294,967,295 (2³²−1)
Arabic
العدد الثنائي الموجب: كل بت يمثل قوة من قوى 2 (من اليمين: 2⁰، 2¹، 2²، ...).
نحوّل من ثنائي لعشري بضرب كل بت في القوة المناسبة ثم الجمع.
مدى 32 بت: من 0 إلى 4,294,967,295.
Signed Integers — 2's Complement Representation الأعداد الموقّعة — تمثيل مكمّل الاثنين

The standard way to represent negative numbers in computers. Range: −2ⁿ⁻¹ to +2ⁿ⁻¹ − 1

Sign bit (MSB): Bit 31 in 32-bit numbers.
• 0 = positive (or zero)
• 1 = negative
2's Complement Value Formula
Value = −b_{n-1}×2^{n-1} + b_{n-2}×2^{n-2} + ... + b₁×2¹ + b₀×2⁰ ↑ MSB contributes NEGATIVE power Example: 1111 1100₂ (8-bit) = −1×2⁷ + 1×2⁶ + 1×2⁵ + 1×2⁴ + 1×2³ + 1×2² + 0×2¹ + 0×2⁰ = −128 + 64 + 32 + 16 + 8 + 4 + 0 + 0 = −4₁₀
Special Value32-bit RepresentationDecimal

Most Positive0111 1111 ... 1111+2,147,483,647
−11111 1111 ... 1111−1

Arabic — شرح مكمّل الاثنين
مكمّل الاثنين هو الطريقة القياسية لتمثيل الأعداد السالبة في الحاسوب.
بت الإشارة (MSB): إذا كان 1 → العدد سالب. إذا كان 0 → موجب أو صفر.
القيمة = (MSB يُحسب كقيمة سالبة) + باقي البتات موجبة.
مدى 32 بت: من -2,147,483,648 إلى +2,147,483,647.
1's Complement مكمّل الواحد

Flip every bit: 0 → 1, 1 → 0. Simple to compute but has two representations of zero (+0 and −0) — a drawback.

1's Complement Examples (8-bit)
+5 = 0000 0101₂ 1's complement of +5: = 1111 1010₂ = −5 in 1's complement +12 = 0000 1100₂ 1's complement: = 1111 0011₂ = −12 in 1's complement
Problem with 1's Complement
+0 = 0000 0000 and −0 = 1111 1111 → two zeros → complicates arithmetic circuits.
Arabic
مكمّل الواحد: نعكس كل بت (0 يصبح 1، 1 يصبح 0).
بسيط الحساب لكن عيبه: يوجد تمثيلان للصفر (+0 و -0) مما يعقد دوائر الحساب.
لذلك لا يُستخدم هذا النظام فعلياً في المعالجات الحديثة.
2's Complement — Step-by-Step Worked Examples مكمّل الاثنين — أمثلة محلولة خطوة بخطوة

Method: Negate a number = Flip all bits (1's complement) + Add 1

Example A: Find 2's complement of +2 (8-bit)

Step-by-step
Step 1: Write +2 in binary: +2 = 0000 0010₂ Step 2: Flip all bits (1's complement): = 1111 1101₂ Step 3: Add 1: 1111 1101 + 1 ----------- 1111 1110₂ ← This is −2 in 2's complement ✓ Verify: −1×2⁷ + (1×2⁶+1×2⁵+1×2⁴+1×2³+1×2²+1×2¹+0) = −128 + 64+32+16+8+4+2+0 = −128 + 126 = −2 ✓

Example B: Find 2's complement of +45 (8-bit)

Step-by-step
Step 1: +45 = 0010 1101₂ Step 2: Flip: 1101 0010₂ Step 3: +1: 1101 0010 + 1 ----------- 1101 0011₂ ← This is −45 in 2's complement ✓

Example C: Convert 1100 0001₂ to decimal (2's complement, 8-bit)

Step-by-step (MSB=1 → negative)
Method 1 — Formula: = −1×2⁷ + 1×2⁶ + 0 + 0 + 0 + 0 + 0 + 1×2⁰ = −128 + 64 + 1 = −63₁₀ Method 2 — Negate and read: Flip: 0011 1110 Add 1: 0011 1111 = 63 → original was −63 ✓
Arabic — شرح الطريقة
طريقة حساب مكمّل الاثنين:
خطوة 1: اكتب العدد بالثنائي.
خطوة 2: اعكس كل البتات (مكمّل 1).
خطوة 3: أضف 1 للنتيجة.

للتحويل من مكمّل 2 لعشري:
إذا كان MSB = 0 → موجب، احسب القيمة العادية.
إذا كان MSB = 1 → سالب، طبّق الصيغة: القيمة = −MSB×2^(n-1) + باقي البتات الموجبة.
Sign Extension توسيع الإشارة

Representing a number using more bits while preserving its value. Rule: replicate the sign bit to fill the new positions.

Examples: 8-bit → 16-bit
+2 (8-bit): 0000 0010 → (16-bit): 0000 0000 0000 0010 (fill with 0s — positive) −2 (8-bit): 1111 1110 → (16-bit): 1111 1111 1111 1110 (fill with 1s — negative) Rule: copy MSB leftward to fill new bits
Arabic
توسيع الإشارة: تمثيل نفس العدد بعدد بتات أكبر مع الحفاظ على قيمته.
القاعدة: انسخ بت الإشارة (MSB) لملء البتات الجديدة على اليسار.
عدد موجب (MSB=0): أضف أصفار على اليسار. عدد سالب (MSB=1): أضف واحدات على اليسار.
يُستخدم في MIPS في: addi، lb، lh، beq، bne.

MIPS Instruction Formats

تنسيقات تعليمات MIPS
R-Format Instructions تعليمات تنسيق R

Used for register arithmetic operations (add, sub, and, or, sll, srl, …)

op
6 bits
rs
5 bits
rt
5 bits
rd
5 bits
shamt
5 bits
funct
6 bits
  • op (opcode): Operation code — for R-format always 000000
  • rs: First source register
  • rt: Second source register
  • rd: Destination register
  • shamt: Shift amount (0 for non-shift operations)
  • funct: Function code (specifies exact operation within op group)

Worked Example: Encode add $t0, $s1, $s2

Step-by-step encoding
$s1 = register 17 → 10001 $s2 = register 18 → 10010 $t0 = register 8 → 01000 op = 0 (R-format) → 000000 shamt = 0 → 00000 funct (add) = 32 → 100000 Binary: 000000 | 10001 | 10010 | 01000 | 00000 | 100000 Hex: 0x02324020
Arabic
تنسيق R: يُستخدم للعمليات بين السجلات. إجمالي 32 بت = 6+5+5+5+5+6.
op = 000000 دائماً لتعليمات R. funct: يحدد العملية الدقيقة (add=32، sub=34...).
المثال: add $t0, $s1, $s2 → نكتب أرقام السجلات بالثنائي ونضعها في الحقول المناسبة.
I-Format Instructions تعليمات تنسيق I

Used for immediate, load/store, and branch instructions.

op
6 bits
rs
5 bits
rt
5 bits
constant or address
16 bits
  • op: Determines the exact instruction (no funct needed)
  • rs: Source register (or base register for memory)
  • rt: Destination register (or source for sw)
  • 16-bit immediate: Constant value (sign-extended to 32 bits) or memory offset
Design Principle 4: Good design demands good compromises — different formats complicate decoding, but allow uniform 32-bit instructions.
Arabic
تنسيق I: للتعليمات التي تحتاج ثابتاً فورياً (addi، lw، sw، beq، bne).
16 بت للثابت تعني: يمكن تمثيل قيم من -32768 إلى +32767.
الثابت يُوسَّع بالإشارة (Sign Extension) ليصبح 32 بت عند الاستخدام.

Practice Questions with Solutions

أسئلة تدريبية مع الحلول
Question 1 — C to MIPS Translation
Translate the following C code to MIPS assembly. Assume: a→$s0, b→$s1, c→$s2, d→$s3, e→$s4

a = b + c - d + 5;
Solution
MIPS Assembly
add $t0, $s1, $s2 # $t0 = b + c sub $t0, $t0, $s3 # $t0 = b + c - d addi $s0, $t0, 5 # a = b + c - d + 5
Arabic — الشرح
خطوة 1: b+c في $t0. خطوة 2: نطرح d. خطوة 3: نضيف الثابت 5 باستخدام addi.
Question 2 — Array Access Translation
Translate to MIPS. Assume: h→$s2, base of A→$s3

A[3] = h + A[5] - A[1];
Solution

Offsets: A[1]=4, A[3]=12, A[5]=20

MIPS Assembly
lw $t0, 20($s3) # $t0 = A[5] (offset = 5×4 = 20) add $t0, $s2, $t0 # $t0 = h + A[5] lw $t1, 4($s3) # $t1 = A[1] (offset = 1×4 = 4) sub $t0, $t0, $t1 # $t0 = h + A[5] - A[1] sw $t0, 12($s3) # A[3] = result (offset = 3×4 = 12)
Arabic
كل عنصر مصفوفة 4 بايت. A[i] → إزاحة = i×4. نحمّل A[5] وA[1]، نحسب، ثم نخزن في A[3].
Question 3 — 2's Complement Conversion
a) Find the 2's complement of +19 (8-bit).
b) Convert 1001 0110₂ to decimal (8-bit, 2's complement).
Solution
Part A: 2's complement of +19
Step 1: +19 = 0001 0011₂ Step 2: Flip (1's comp): 1110 1100₂ Step 3: Add 1: 1110 1100 + 1 ----------- 1110 1101₂ ← −19 in 2's complement ✓ Verify: −128 + 64+32+8+4+1 = −128+109 = −19 ✓
Part B: Convert 1001 0110₂
MSB = 1 → negative number Method 1 (Formula): = −1×2⁷ + 0×2⁶ + 0×2⁵ + 1×2⁴ + 0×2³ + 1×2² + 1×2¹ + 0×2⁰ = −128 + 0 + 0 + 16 + 0 + 4 + 2 + 0 = −106₁₀ Method 2 (Negate & read): Flip: 0110 1001 Add 1: 0110 1010 = 64+32+8+2 = 106 → Original = −106 ✓
Question 4 — 1's Complement
Find the 1's complement of the following 8-bit numbers:
a) +7    b) +100    c) −0 (what does this mean?)
Solution
1's Complement Solutions
a) +7 = 0000 0111₂ 1's comp = 1111 1000₂ → represents −7 b) +100 = 0110 0100₂ 1's comp = 1001 1011₂ → represents −100 c) +0 = 0000 0000₂ → 1's comp = 1111 1111₂ = "−0" This is the problem! Two representations of zero.
Arabic
مكمّل الواحد: نعكس كل البتات فقط. المشكلة: يوجد +0 و -0 (تمثيلان للصفر) مما يعقد الحسابات. لذلك نستخدم مكمّل الاثنين عملياً.
Question 5 — R-Format Encoding
Encode the MIPS instruction sub $s0, $t0, $t1 into binary and hexadecimal.
Note: sub funct code = 34 (100010₂)
Solution
R-Format Encoding
Instruction: sub $s0, $t0, $t1 rd = $s0 → register 16 → 10000 rs = $t0 → register 8 → 01000 rt = $t1 → register 9 → 01001 op = 0 (R-format) → 000000 shamt = 0 → 00000 funct (sub) = 34 → 100010 Binary: 000000 | 01000 | 01001 | 10000 | 00000 | 100010 = 0000 0001 0000 1001 1000 0000 1000 10₂ Hex: = 0x01098022
Question 6 — RISC vs CISC Analysis
A CISC machine executes a task in 50 instructions averaging 8 clock cycles each. A RISC machine needs 200 instructions averaging 1.2 cycles each. The RISC clock is 1.5× faster. Which is faster?
Solution
Performance Analysis
CPU Time = Instruction Count × CPI × Clock Period Let CISC clock period = T: CISC time = 50 × 8 × T = 400T RISC clock period = T/1.5 (faster clock): RISC time = 200 × 1.2 × (T/1.5) = 240T/1.5 = 160T RISC time (160T) < CISC time (400T) → RISC is 400/160 = 2.5× FASTER ✓
Arabic
CISC: 50 × 8 × T = 400T. RISC: 200 × 1.2 × (T/1.5) = 160T.
RISC أسرع 2.5 مرة رغم استخدامه تعليمات أكثر — لأن كل دورة أقصر وعدد الدورات لكل تعليمة أقل بكثير.
Question 7 — If-Else Translation
Translate to MIPS. Assume: x→$s0, y→$s1, z→$s2, result→$s3

if (x != y) { result = x + z; } else { result = x - z; }
Solution
MIPS Assembly
beq $s0, $s1, Else # if (x == y) goto Else add $s3, $s0, $s2 # result = x + z j Exit # jump past else Else: sub $s3, $s0, $s2 # result = x - z Exit: ... # continue
Arabic
الشرط x≠y: نعكسه في MIPS فنستخدم beq (يقفز إذا تساويا = إذا كان الشرط خاطئاً) للذهاب لـ Else.
Question 8 — Sign Extension
Sign-extend the following 8-bit values to 16 bits:
a) 0101 1010₂    b) 1010 0011₂
Solution
Sign Extension
a) 0101 1010₂ — MSB = 0 (positive) → 0000 0000 0101 1010₂ (extend with 0s) Value = +90 (unchanged) b) 1010 0011₂ — MSB = 1 (negative) → 1111 1111 1010 0011₂ (extend with 1s) Verify: = −128+32+2+1 = −93 in 8-bit Extended: −32768+... = −93 (same value) ✓
