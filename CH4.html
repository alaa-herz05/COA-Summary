Characteristics of Memory Systems

خصائص أنظمة الذاكرة
Location الموقع

Refers to whether memory is internal or external to the computer.

  • Internal memory — includes main memory (RAM), cache, and CPU registers.
  • Cache — a special form of internal memory; faster than RAM, closer to the CPU.
  • External memory — peripheral storage (HDD, SSD) accessed via I/O controllers.
Arabic Explanation
الذاكرة تُقسَّم حسب موقعها إلى داخلية وخارجية.
الداخلية تشمل: الـ RAM (الذاكرة الرئيسية)، الكاش (أسرع من RAM وأقرب للمعالج)، والسجلات (Registers) داخل المعالج نفسه.
الخارجية: الهارد والـ SSD — يصل إليها المعالج عبر وحدات الـ I/O فقط.
Capacity السعة

Memory size is typically expressed in bytes (KB, MB, GB…).

Arabic
السعة = كمية البيانات التي تستوعبها الذاكرة، تُقاس بالبايت.
Unit of Transfer وحدة النقل

For internal memory, equals the number of electrical lines into/out of the memory module.

Arabic
عدد الخطوط الكهربائية الداخلة والخارجة من وحدة الذاكرة — يحدد كم بيانات تُنقل في كل عملية.

Arabic Explanation
Sequential: تسلسلي — لازم تمر على البيانات بالترتيب (مثل الشريط المغناطيسي). بطيء.
Direct: مباشر — تقفز لمنطقة تقريبية ثم تبحث بداخلها (مثل HDD).
Random: عشوائي — أي عنوان تصله مباشرةً بنفس الوقت (مثل RAM والكاش). الأسرع.
Associative: ترابطي — تبحث بالمحتوى مش بالعنوان، يُستخدم في الكاش.
Capacity & Performance Metrics مقاييس الأداء
  • Access Time — Time to read or write a unit of data.
  • Cycle Time — Minimum time between two successive accesses (access time + recovery).
  • Transfer Rate — Rate at which data is moved to/from memory.
Key rule: Faster memory = smaller capacity = higher cost. Cache is the optimal middle ground between register speed and RAM capacity.
Arabic
Access Time: وقت القراءة/الكتابة.
Cycle Time: الحد الأدنى بين عمليتَي وصول متتاليتين (يشمل وقت الاسترداد بعد كل عملية).
Transfer Rate: سرعة نقل البيانات.

القاعدة الذهبية: كلما زادت السرعة قلّت السعة وارتفع السعر. الكاش هو الحل الوسط بين سرعة السجلات وسعة الـ RAM.

The Cache Principle

مبدأ الكاش وآلية عمله
Why Cache Exists لماذا يوجد الكاش؟

The CPU is far faster than main memory. Without cache, the CPU wastes cycles waiting for data — a speed gap bottleneck. Cache stores the most frequently used data right next to the CPU.

Arabic
المعالج أسرع بكثير من الـ RAM، فبدون الكاش يضطر للانتظار عند كل طلب بيانات (Bottleneck). الكاش ذاكرة صغيرة جداً وسريعة جداً تجلس بين المعالج والـ RAM وتحتفظ بأكثر البيانات استخداماً.
Principle of Locality مبدأ المحلية

Cache works because real programs exhibit locality of reference:

Temporal Locality
Data used recently will likely be used again soon.
Example: a loop variable accessed every iteration.
Spatial Locality
If one address is accessed, nearby addresses will likely be accessed soon.
Example: sequential array elements.
Arabic
الكاش يعمل بسبب ظاهرة طبيعية في البرامج تسمى "المحلية":
المحلية الزمنية (Temporal): البيانات المستخدمة مؤخراً ستُستخدم مجدداً قريباً (مثل متغير في حلقة loop).
المحلية المكانية (Spatial): إذا استُخدم عنوان معين، العناوين المجاورة له ستُستخدم قريباً (مثل عناصر مصفوفة متتالية).
Cache Hit & Miss الإصابة والإخفاق
  • ✓ Cache Hit — Requested data found in cache → served immediately (fast).
  • ✗ Cache Miss — Data not in cache → must fetch from slower RAM.
  • Hit Rate — Fraction of accesses that result in a hit. Higher = better performance.
Arabic
Cache Hit (إصابة): المعالج وجد البيانات في الكاش ← سريع جداً ✓
Cache Miss (إخفاق): البيانات غير موجودة في الكاش ← يرجع للـ RAM ✗
Hit Rate: النسبة المئوية للعمليات التي تجد بياناتها في الكاش — كلما ارتفعت كان الأداء أفضل.

3

Mapping Functions

دوال التعيين — كيف تُخصَّص كتل RAM لخطوط الكاش
Core Problem
There are far fewer cache lines than main memory blocks. An algorithm is required to decide which cache line hosts which RAM block. Three techniques exist.
Arabic
عدد خطوط الكاش أقل بكثير من عدد كتل الذاكرة الرئيسية، لذلك نحتاج خوارزمية لتحديد أي خط كاش يستضيف أي كتلة RAM. هناك ثلاث طرق.
① Direct Mapping التعيين المباشر

Principle: Each RAM block maps to exactly one specific cache line — no flexibility.

Formula:   i = j mod m    ( i = cache line, j = RAM block number, m = total cache lines )

Address structure:

Direct Mapping — Address Breakdown
|  Tag (s-r bits)  |  Line Number (r bits)  |  Word/Byte (w bits)  |
Key Equations
Address length = (s + w) bits Number of blocks in RAM = 2^s Number of cache lines = m = 2^r Tag size = (s - r) bits
Advantages ✓
  • Simple & fast lookup
  • Low hardware cost
  • No replacement algorithm needed
Disadvantage ✗
  • Conflict Misses — if two frequently used blocks map to the same line, they constantly evict each other → thrashing.
Arabic Explanation
كل كتلة RAM لها خط واحد فقط محدد مسبقاً في الكاش ولا تستطيع الذهاب لغيره.
المعادلة: i = j mod m (رقم الخط = رقم الكتلة % عدد الخطوط).
العنوان مقسّم لثلاثة أجزاء: Tag (يعرّف الكتلة) + Line Number (يحدد الخط) + Word (يحدد البايت داخل الكتلة).
المشكلة: Conflict Miss — إذا احتاج البرنامج كتلتين تذهبان لنفس الخط، ستطرد كل منهما الأخرى باستمرار وهذا يُبطّئ الأداء كثيراً.
① Victim Cache ذاكرة الكاش الضحية

Proposed to reduce conflict misses of direct-mapped caches without losing their fast access time.

  • A fully associative cache, typically 4–16 lines.
  • Sits between L1 (direct-mapped) and L2.
  • Its job: catch "victims" — blocks evicted from L1 due to conflicts.

How it works:

  • Eviction: A block kicked out of L1 goes to the Victim Cache instead of L2.
  • On L1 miss: CPU simultaneously checks the Victim Cache.
  • Hit in Victim Cache: the block is swapped back into L1; the displaced L1 block moves to Victim Cache.
  • Miss in both: CPU fetches from L2 or main memory.
Arabic Explanation
الـ Victim Cache كاش صغير جداً (4–16 خط) Fully Associative يجلس بين L1 و L2.
مهمته: يستقبل الكتل التي طُردت من L1 بسبب Conflict — بدل ما تضيع في L2 مباشرةً.
عند Miss في L1: المعالج يفحص Victim Cache في نفس الوقت.
إذا وجدها (Victim Hit): تُبادَل الكتلتان بين L1 والـ Victim Cache (Swap).
إذا لم يجدها: يذهب للـ L2 أو الـ RAM.
الفائدة: يحل مشكلة Conflict Misses دون التأثير على سرعة L1.
② Associative (Fully Associative) Mapping التعيين الترابطي الكامل

Principle: Any RAM block can go into any cache line — complete flexibility.

Address Breakdown — Associative
|  Tag (s bits) — full block identifier  |  Word/Byte (w bits)  | (No line-number field needed)
Key Equations
Address length = (s + w) bits Tag size = s bits ← entire block identity Number of cache lines = undetermined (flexible)
Advantages ✓
  • Maximum flexibility → highest potential hit rate
  • No conflict misses
Disadvantages ✗
  • Must compare tag against ALL cache lines simultaneously → complex parallel hardware
  • Expensive; impractical for large caches
Arabic Explanation
أي كتلة من RAM تستطيع الذهاب لأي خط في الكاش — لا قيود على الإطلاق.
العنوان مقسّم لجزأين فقط: Tag (يمثل كامل معرّف الكتلة) + Word.
لماذا Tag كبير؟ لأنه يجب مقارنة كامل هوية الكتلة مع كل الخطوط دفعةً واحدة.
المشكلة: البحث عن الكتلة يتطلب مقارنة كل الخطوط في نفس اللحظة → دوائر إلكترونية معقدة ومكلفة جداً.
③ Set Associative Mapping التعيين الترابطي بالمجموعات

Principle: The best of both worlds. Cache is divided into sets; each set contains k lines. A given block always maps to one specific set (like direct mapping), but can occupy any line within that set (like associative).

Block → fixed set (determined by address bits) → any line within that set
Address Breakdown — Set Associative
|  Tag (s-d bits)  |  Set Number (d bits)  |  Word/Byte (w bits)  |
Key Equations
Number of sets = v = 2^d Lines per set = k Total lines in cache = m = k × v = k × 2^d Cache size = k × 2^(d+w) words or bytes Tag size = (s - d) bits

Special cases:

  • k = 1 → Degenerates into Direct Mapping
  • k = 2 → 2-Way Set Associative (most common in CPUs)
  • k = 4 or 8 → 4-Way / 8-Way Set Associative
  • k = m → Degenerates into Fully Associative
Arabic Explanation
الحل الوسط الذكي بين Direct وAssociative.
الكاش مقسّم لمجموعات (Sets)، كل مجموعة تحتوي k خطوط.
الكتلة تذهب دائماً لمجموعة واحدة محددة بناءً على بتات العنوان (مثل Direct Mapping)، لكن داخل المجموعة تذهب لأي خط (مثل Associative).
مثال: 2-Way Set Associative = كل مجموعة فيها خطّان، الكتلة تختار بينهما بحرية.
العنوان = Tag + Set Number (يحدد المجموعة) + Word.
هذا الأسلوب هو الأكثر استخداماً في المعالجات الحديثة.

Replacement Algorithms

خوارزميات الاستبدال

When the cache is full and a new block must be loaded, an existing block must be evicted. Direct mapping has no choice (one line per block). Associative and set-associative caches need a replacement policy. Must be implemented in hardware for speed.

Arabic
عند امتلاء الكاش وجلب كتلة جديدة، يجب حذف كتلة قديمة.
الـ Direct Mapping لا يحتاج خوارزمية (خط واحد = لا خيار).
الـ Associative والـ Set Associative يحتاجان خوارزمية — ويجب تنفيذها بالـ Hardware لضمان السرعة.
LRU — Least Recently Used الأقل استخداماً مؤخراً

Most Effective

Evicts the block that has gone the longest without being referenced. Exploits temporal locality.

Implementation: a use-time counter per line; simplest and most popular.

Arabic
يحذف الكتلة التي مضى على آخر استخدام لها أطول وقت. يعتمد على مبدأ المحلية الزمنية. الأفضل أداءً والأشهر استخداماً. يُنفَّذ بعداد زمني لكل خط.
FIFO — First In, First Out الأول دخولاً الأول خروجاً

Evicts the block that has been in cache the longest, regardless of recent use.

Implementation: circular (round-robin) buffer — easy to build.

Arabic
يحذف أقدم كتلة دخلت الكاش بغض النظر عن استخدامها الأخير. يُنفَّذ بـ Circular Buffer. سهل لكن أقل كفاءة من LRU.
LFU — Least Frequently Used الأقل استخداماً إجمالاً

Evicts the block with the fewest total references. Implemented with a reference counter per line.

Drawback
A historically popular block accumulates a high count and stays in cache even when it is no longer needed — hurting performance.
Arabic
يحذف الكتلة الأقل استخداماً من حيث عدد المرات الكلية. يُنفَّذ بعداد تكرار لكل خط.
عيبه: كتلة استُخدمت كثيراً تاريخياً لكنها غير مطلوبة الآن ستبقى في الكاش بسبب عدادها العالي.

FIFOOldest entryCircular bufferAverageالأقدم دخولاً

Write Policy

سياسة الكتابة

The problem: When the CPU writes data to cache, when should main memory be updated? Two strategies exist.

Arabic
عندما يكتب المعالج بيانات للكاش، متى يجب تحديث الـ RAM؟ هناك مدرستان.
Write Through الكتابة المتزامنة

Every write to cache simultaneously writes to main memory.

  • RAM always consistent with cache
  • Simplest design
  • Safe for I/O modules — they always see current data
Main Drawback ✗
Every write goes to slow RAM → heavy bus traffic → potential bottleneck.
Arabic
عند كل كتابة في الكاش، تُكتب البيانات في نفس اللحظة في الـ RAM.
الـ RAM دائماً محدّثة ومتزامنة ← آمن وبسيط.
العيب: يولّد كثيراً من عمليات الكتابة للـ RAM ← ازدحام على الـ Bus (Bottleneck).
Write Back الكتابة المتأخرة

Writes go to cache only. RAM is updated only when the modified line is evicted (tracked by a dirty bit).

  • Far fewer RAM writes → higher performance
  • Dirty bit marks lines that differ from RAM
Drawbacks ✗
  • Complex circuitry and potential bottleneck at eviction
  • RAM may be stale → I/O modules must access data through cache
  • Data loss risk on power failure
Arabic
الكتابة في الكاش فقط. الـ RAM تُحدَّث فقط عند طرد الخط (يُستخدم "Dirty Bit" لتتبع الخطوط المعدَّلة).
الميزة: أقل عمليات كتابة للـ RAM ← أسرع أداء.
العيوب: تصميم أكثر تعقيداً، الـ RAM قد تكون outdated ← مشكلة مع الـ I/O.
CriterionWrite ThroughWrite Back
RAM update timingEvery write (immediate)Only on eviction

Line Size

حجم السطر — كمية البيانات المنقولة عند كل Miss
What is Line Size? ما هو حجم السطر؟

On a cache miss, the CPU does not fetch only the requested byte — it loads a whole block (line) from RAM. Line size = how large that block is.

Larger line size →
Exploits spatial locality — nearby data already in cache → fewer future misses.
Too large ✗
  • Loads unused data (cache pollution)
  • Longer transfer time per miss
  • Wastes cache space; fewer distinct lines fit
Optimal: A moderate size — not too small, not too large. Modern CPUs: typically 64 bytes per cache line.
Arabic Explanation
عند Cache Miss، المعالج لا يجلب البيانات المطلوبة فقط — بل يجلب "كتلة" كاملة من الـ RAM.
سطر كبير: يستفيد من Spatial Locality — البيانات المجاورة موجودة مسبقاً في الكاش ← أقل misses مستقبلاً.
سطر كبير جداً: يجلب بيانات لن تُستخدم (Pollution) ← يضيع مساحة الكاش ويطول وقت كل Miss.
الحجم المثالي في المعالجات الحديثة: 64 بايت.

Multilevel Caches

الكاش متعدد المستويات — L1, L2, L3
Why Multiple Levels? لماذا تعدد المستويات؟

Advances in chip density made it possible to place cache on the same die as the CPU (on-chip cache). This eliminates external bus access for common data, dramatically reducing latency and freeing the bus for other transfers.

مع تطور تقنية الرقاقات، أصبح ممكناً وضع الكاش داخل نفس الشريحة مع المعالج. هذا يعني الوصول للبيانات الشائعة دون استخدام الـ Bus الخارجي إطلاقاً — أسرع بكثير ويُحرّر الـ Bus لعمليات أخرى.
LevelLocationTypical SizeSpeedPurposeبالعربي
L1 On-chip (per core) 32–64 KB ~1 ns (fastest) First-level, fastest access for CPU داخل المعالج مباشرةً
L2 On-chip or near-chip 256 KB – 4 MB ~4 ns Handles L1 misses يعالج ما فات L1
L3 Shared across cores 4 – 64 MB ~10 ns Shared last-resort before RAM مشترك بين الأنوية — آخر خط قبل RAM
Benefits & Trade-offs الفوائد والتعقيدات
  • Reduced bus traffic: If L1 hits, the external bus is never used — free for other transfers.
  • Performance: Effective hit rate is compounded — even a modest L2 hit rate significantly cuts RAM accesses.
  • Speed-capacity balance: L1 tiny & fast; L3 large & slightly slower — best of both.
Complexity Trade-off ✗
Using multiple levels complicates every design decision: size, replacement algorithm, and write policy — each level may need different settings.
Arabic
تقليل Bus Traffic: إذا وُجدت البيانات في L1، الـ Bus الخارجي لا يُستخدم إطلاقاً ← يبقى حراً لتحويلات أخرى.
رفع الأداء: معدل الإصابة يُحسب بشكل مركّب — حتى Hit Rate متواضع في L2 يقلل كثيراً من الوصول للـ RAM.
التوازن: L1 صغير وسريع جداً، L3 كبير وأبطأ قليلاً.
التعقيد: تعدد المستويات يُعقّد جميع قرارات التصميم — الحجم، الاستبدال، وسياسة الكتابة.
